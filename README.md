# BOTC Bench Storyteller Workspace

一个本地运行的《血染钟楼》说书人局面编辑器与推理 benchmark。前端使用 React + TypeScript，后端使用 FastAPI + SQLite；“Codex 辅助”按钮通过后端受控调用本机 `codex exec`，只在只读沙箱中分析当前局面。

## 功能

- 在三大官方基础剧本间切换：Trouble Brewing / 暗流涌动、Bad Moon Rising / 黯月初升、Sects & Violets / 梦殒春宵。
- 创建 5–20 人局面，维护角色配比、座次、玩家名、真实角色、阵营、生死与多种状态标记。
- 自动记录局面变化并保存到本机 SQLite，刷新后可从本地存档继续编辑或回放。
- 游戏时间线支持逐条回放、播放/暂停、调速、拖动进度与完整事件列表；可从任意配比完整的历史时刻创建独立分支。
- 引导式夜间清单按官方首夜/其他夜晚顺序推进，高亮下一步玩家，记录选择、收到的信息及说书人决定，并核对持续效果。
- 把当前局面和问题交给本机 Codex 做配比检查、矛盾分析或说书人辅助；Codex 无权直接修改局面。
- 官方英文角色文本与 TPI 官方简体中文文本并列保留；剧本、规则、FAQ 的原始链接集中存放在相邻 `reference/` 目录。

## 本地运行

需要 Python 3.9+、[uv](https://docs.astral.sh/uv/)、Node.js 22.12+ 和已经登录的 Codex CLI。

```bash
uv sync --dev
cd frontend && npm install
```

分别启动后端与前端：

```bash
uv run uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
cd frontend && npm run dev
```

打开 `http://127.0.0.1:5173`。Vite 会将 `/api` 代理到 FastAPI。生产构建后，FastAPI 也会自动托管 `frontend/dist`。

默认启用本地 Codex harness；可通过环境变量关闭或调整超时：

```bash
CODEX_HARNESS_ENABLED=false
CODEX_HARNESS_TIMEOUT_SECONDS=120
CODEX_MODEL=gpt-5.6-terra
```

调用固定使用一次性的 `codex exec --ephemeral --sandbox read-only`，不接受来自浏览器的命令、模型或目录参数。后端只读取当前剧本的四份白名单资料并把正文内联到提示词；Codex 在空临时目录中启动、忽略用户配置，并关闭 shell、插件、Apps、浏览器、计算机控制、图像、技能搜索与网页搜索能力。进程只继承登录和网络连接所需的最小环境变量，继续使用正常 Codex 凭据存储以支持令牌刷新；同一时间最多运行一个本地 Codex 进程。

## 记录、回放与分支

- **自动记录**：修改角色、座次、生死、阵营、标记、阶段和备注时，底部「游戏时间线」会保留当时的完整局面。连续输入同一文本字段会合并为一条尚未保存的记录。
- **补充事件**：使用「添加事件」选择「行动」「信息」或「说书人记录」，记录实际告知的信息、行动选择与结果、提名投票和公告。行动与信息可通过「参与玩家」指定行动者或信息来源，以及多个目标或接收者；玩家姓名和座次按当时快照显示。这些桌面上发生的事件需要手动输入；时间线不会自动获知现实对局中的发言或行动。
- **保存**：编辑停顿 1.5 秒后自动保存，也可点击「保存局面」或按 `Cmd/Ctrl+S`。当前配比总数不完整、局名或标记名称为空时，自动保存等待修正；失败后会明确提示，并暂停自动重试，修正问题后点击保存重试。离开有未保存修改的页面时会提示。
- **回放**：从本地存档载入游戏后，在底部播放、逐条前后切换、拖动进度条，或使用「跳转阶段」查看某个白天或夜晚的起点。「全部记录」按连续阶段分组，支持筛选行动、信息、死亡、复活与角色变化；返回已出现过的阶段时仍保留实际记录顺序。死亡、复活和角色变化从相邻快照识别，也适用于旧存档。魔典和检查器显示所选时刻的角色与状态，回放期间只能查看；「返回当前局面」恢复编辑。
- **分支**：回放到所需时刻后点击「从此处分支」。系统先保存当前原局（如有修改），再创建带来源信息的独立存档，保留截至所选时刻的历史，可继续编辑。原局的后续过程仍然保留。
- **旧存档**：首次载入时以既有局面作为「旧存档起点」，此前未记录的过程无法补回。

时间线与原局在同一次 SQLite 写入中保存，已保存的历史只能追加。旧版本接口未提交时间线时，后端仍会为更新后的局面追加快照。历史快照允许暂时未完成的配比或标记名称以保留编辑过程，但创建分支时需选择配比总数完整且标记名称已填写的时刻。

## 引导式夜间清单

右侧「今晚清单」中点击「开始首夜」；白天点击「开始下一夜」。选择步骤可查看官方中英夜间提醒，记录玩家选择、实际收到的信息和说书人决定，再完成步骤。下一步玩家会在魔典中高亮；爪牙/恶魔信息步骤会高亮相应玩家组。此流程无需 Codex 在线。

- 清单记录随局面自动保存。刷新后从「本地存档」载入即可继续；时间线回放只读，分支保留当时的清单进度。每个新夜晚建立新清单，往夜记录保存在时间线。
- 死亡、醉酒、一次性及条件能力仍列出供说书人核对，填写原因后可跳过；已完成/跳过的步骤可重新打开。角色变化后用「补入新角色行动」添加新步骤，原记录保留；已失效步骤由说书人跳过。
- 可添加关联玩家与参考能力的步骤，用于获得能力或额外裁定，并用上下箭头调整顺序。
- 玩家标记的「持续到」会出现在持续效果提醒中。说书人核对后选择保留或移除，全部步骤与提醒处理后可进入白天。到期文字由说书人判断，不自动删除标记。

清单排序与并列显示的中英提醒来自 TPI；步骤筛选、完成状态及辅助提示属于本地工作流，条件结算仍由说书人决定。
