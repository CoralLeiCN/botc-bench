# BOTC Bench Storyteller Workspace

一个本地运行的《血染钟楼》说书人局面编辑器与推理 benchmark。前端使用 React + TypeScript，后端使用 FastAPI + SQLite；“Codex 辅助”按钮通过后端受控调用本机 `codex exec`，只在只读沙箱中分析当前局面。

## 功能

- 在三大官方基础剧本间切换：Trouble Brewing / 暗流涌动、Bad Moon Rising / 黯月初升、Sects & Violets / 梦殒春宵。
- 创建 5–20 人局面，维护角色配比、座次、玩家名、真实角色、阵营、生死与多种状态标记。
- 分别记录真实身份、展示身份、公开声明与私人信息；使用「以此玩家视角查看」预览受限局面，以及该玩家代理实际收到的完整输入。
- 自动记录局面变化并保存到本机 SQLite，刷新后可从本地存档继续编辑或回放。
- 游戏时间线支持逐条回放、播放/暂停、调速、拖动进度与完整事件列表；可从任意配比完整的历史时刻创建独立分支。
- 提名与投票面板记录提名双方、逐人投票、计票权重、待处决候选人与剩余亡者票；所有操作进入时间线并供后续分析引用。
- 引导式夜间清单按官方首夜/其他夜晚顺序推进，高亮下一步玩家，记录选择、收到的信息及说书人决定，并核对持续效果。
- 把当前局面和问题交给本机 Codex 做配比检查、矛盾分析或说书人辅助；Codex 无权直接修改局面。
- 官方英文角色文本与 TPI 官方简体中文文本并列保留；剧本、规则、FAQ 的原始链接集中存放在相邻 `reference/` 目录。

## 本地运行

需要 Python 3.9+、[uv](https://docs.astral.sh/uv/)、Node.js 22.12+ 和已经登录的 Codex CLI。

```bash
uv sync --dev
cd frontend && npm install
```

分别启动后端与前端：

```bash
uv run uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
cd frontend && npm run dev
```

打开 `http://127.0.0.1:5173`。Vite 会将 `/api` 代理到 FastAPI。生产构建后，FastAPI 也会自动托管 `frontend/dist`。

默认启用本地 Codex harness；可通过环境变量关闭或调整超时：

```bash
CODEX_HARNESS_ENABLED=false
CODEX_HARNESS_TIMEOUT_SECONDS=120
CODEX_MODEL=gpt-5.6-terra
```

调用固定使用一次性的 `codex exec --ephemeral --sandbox read-only`，不接受来自浏览器的命令、模型或目录参数。后端只读取当前剧本的四份白名单资料并把正文内联到提示词；Codex 在空临时目录中启动、忽略用户配置，并关闭 shell、插件、Apps、浏览器、计算机控制、图像、技能搜索与网页搜索能力。进程只继承登录和网络连接所需的最小环境变量，继续使用正常 Codex 凭据存储以支持令牌刷新；同一时间最多运行一个本地 Codex 进程。

## 记录、回放与分支

- **自动记录**：修改角色、座次、生死、阵营、标记、阶段和备注时，底部「游戏时间线」会保留当时的完整局面。连续输入同一文本字段会合并为一条尚未保存的记录。
- **提名与投票**：在检查器中设置白天与天数，展开「提名与投票」，选择双方并发起提名。逐人记录投票或未投票，支持「其余记为未投票」；计票权重可按角色能力调整。完成计票后锁定结果、消耗本轮亡者票并更新候选人。取消投票保留提名与已录入信息，不消耗亡者票。进行中的投票需先完成或取消才能切换阶段、天数、剧本或人数。
- **亡者票与历史**：玩家检查器可修正亡者票余额，复活时恢复可用状态。新的一天按天数查看独立提名记录，已用亡者票不会每日重置。旧存档默认亡者票可用，请按实际对局修正。回放及分支保留对应时刻的投票与余额；历史中的玩家名称与座位按录入时保存。
- **候选人与裁定**：候选人按常规门槛与最高票计算，最高票平票时无人待处决；不会自动执行处决或改变玩家生死。特殊角色裁定、流放与补记错误请在时间线说明，或从相应时刻创建分支修正。实现依据与核验日期见 [投票来源记录](reference/voting-sources.json)；以上是本工具行为说明，并非官方规则原文。
- **补充事件**：使用「添加事件」选择「行动」「信息」或「说书人记录」，记录实际告知的信息、行动选择与结果、特殊裁定和公告。行动与信息可通过「参与玩家」指定行动者或信息来源，以及多个目标或接收者；玩家姓名和座次按当时快照显示。这些桌面上发生的事件需要手动输入；时间线不会自动获知现实对局中的发言或行动。
- **分析证据**：Codex 辅助接收当前查看时刻的局面与截至该时刻的事件、备注和精确状态变化；回放时不会传入后续事件，可按事件 ID 引用提名与投票证据。
- **保存**：编辑停顿 1.5 秒后自动保存，也可点击「保存局面」或按 `Cmd/Ctrl+S`。当前配比总数不完整、局名或标记名称为空时，自动保存等待修正；失败后会明确提示，并暂停自动重试，修正问题后点击保存重试。离开有未保存修改的页面时会提示。
- **回放**：从本地存档载入游戏后，在底部播放、逐条前后切换、拖动进度条，或使用「跳转阶段」查看某个白天或夜晚的起点。「全部记录」按连续阶段分组，支持筛选行动、信息、死亡、复活与角色变化；返回已出现过的阶段时仍保留实际记录顺序。死亡、复活和角色变化从相邻快照识别，也适用于旧存档。魔典和检查器显示所选时刻的角色与状态，回放期间只能查看；「返回当前局面」恢复编辑。
- **分支**：回放到所需时刻后点击「从此处分支」。系统先保存当前原局（如有修改），再创建带来源信息的独立存档，保留截至所选时刻的历史，可继续编辑。原局的后续过程仍然保留。
- **撤销 / 重做**：顶部箭头或 `Cmd/Ctrl+Z`、`Cmd/Ctrl+Shift+Z`（也支持 `Ctrl+Y`）恢复最近 100 步局面修改；连续输入合并为一步，新修改清空重做栈。文本输入框保留原生文本撤销快捷键。撤销与重做也会追加时间线快照，因此已经保存的历史和手工事件不会被删除；载入、新建、导入或复制游戏时开始新的撤销栈。
- **草稿恢复**：每次局面变化立即缓存到当前浏览器，包括未完成的配比、空名称、时间线及撤销栈。刷新后自动恢复；重新打开浏览器时使用最近的缓存，各标签页分别保存。若原存档版本已变化或被删除，则作为独立副本恢复，避免覆盖其他页面的修改。存储被禁用、已满或草稿损坏时会明确提示；浏览器缓存被清除后只能依赖 SQLite 存档或 JSON 备份。
- **复制 / JSON 备份**：顶部「存档操作」可复制当前存档，或导入 / 导出版本化 `botc-bench-game` JSON。复制和导出先保存当前修改（配比等配置需完整）；备份包含完整时间线、分支来源与已完成的分析。导入经过结构、剧本角色及分析快照校验，总是创建独立存档，可重复导入同一场景；不覆盖现有游戏。导出包含真实角色与说书人备注，请按完整魔典保管。
- **保存分析**：触发 Codex 前先保存局面；服务器从指定的不可变时间线记录读取分析上下文，并保存问题、所选玩家、分析视角、输入摘要、答案、时间、耗时和完整快照；调用前校验完整输入与预览一致。即使分析期间修改或切换游戏，结果仍归属原存档。在「已保存分析」中展开答案，并点击「查看原始局面」回放当时的魔典。分支只继承截至分支时刻的分析。玩家模式只显示本次受限视角的回答；完整历史分析仅在说书人视角中查看。AI 分析不是官方裁定。
- **旧存档**：首次载入时以既有局面作为「旧存档起点」，此前未记录的过程无法补回。

时间线与原局在同一次 SQLite 写入中保存，已保存的历史只能追加。旧版本接口未提交时间线时，后端仍会为更新后的局面追加快照。历史快照允许暂时未完成的配比或标记名称以保留编辑过程，但创建分支时需选择配比总数完整且标记名称已填写的时刻。

## 玩家视角与代理输入

这是应用的可见性策略。说书人在玩家检查器中分别维护：

- **真实角色 / 真实阵营**：用于魔典、配比与说书人分析。
- **展示角色 / 告知阵营**：玩家被告知的身份，独立于真实身份；修改真实身份不会自动改写这些字段。
- **公开声明**：该玩家公开声称的角色、信息或发言，所有玩家都可见，代理不会将其当作已验证的真实身份。
- **私人信息**：仅该玩家实际收到的信息。手动记录夜间结果、获知的队友、恶魔伪装或私聊原话；系统不会从真实角色自动推导这些信息。
- **公开信息**：在「局面阶段与全局备注」中维护公告、提名、投票及其他所有玩家已知的事件。

选中座位后在「玩家检查器」中点击「以此玩家视角查看」，可在顶栏切换玩家或返回说书人视角。玩家页面只显示座次、姓名、生死、公开声明、公开信息及该玩家自己的展示身份和私人信息。真实角色、真实阵营、状态标记、角色配比、局名、说书人备注、夜间清单、其他玩家的私人信息和说书人时间线都不会进入受限视图。夜间清单可能含尚未交付的信息与结算依据，只有另行记录到「私人信息」中的内容才进入玩家输入。死亡或游戏结束不会自动公开这些数据。回放中进入玩家视角时，只使用选定快照里当时已记录的信息。

「代理输入预览」展示完整提示词，包括固定参考资料、受限 JSON 和当前问题；预览无需登录或启用 Codex。快捷问题先填入输入框，核对预览后点击「触发本地 Codex」。后端使用同一构建函数生成预览和实际输入，并核对提示词摘要；输入发生变化时拒绝使用旧预览。切换玩家、视角、问题或局面后，旧分析结果会清除，迟到的结果也不会显示到新视角。

旧存档缺失的展示身份、公开声明和私人信息保持未记录，不会从真实角色或历史说书人备注补填。新字段与快照一同保存、回放及分支。本功能是本地说书人工作区的视角预览，不提供独立玩家账号或访问权限隔离；浏览器仍属于说书人工作区。功能参考来源见 [玩家身份与可见性来源](reference/README.md#玩家身份与可见性)。

## 引导式夜间清单

右侧「今晚清单」中点击「开始首夜」；白天点击「开始下一夜」。选择步骤可查看官方中英夜间提醒，记录玩家选择、实际收到的信息和说书人决定，再完成步骤。下一步玩家会在魔典中高亮；爪牙/恶魔信息步骤会高亮相应玩家组。此流程无需 Codex 在线。

- 清单记录随局面自动保存。刷新后从「本地存档」载入即可继续；时间线回放只读，分支保留当时的清单进度。每个新夜晚建立新清单，往夜记录保存在时间线。
- 死亡、醉酒、一次性及条件能力仍列出供说书人核对，填写原因后可跳过；已完成/跳过的步骤可重新打开。角色变化后用「补入新角色行动」添加新步骤，原记录保留；已失效步骤由说书人跳过。
- 可添加关联玩家与参考能力的步骤，用于获得能力或额外裁定，并用上下箭头调整顺序。
- 玩家标记的「持续到」会出现在持续效果提醒中。说书人核对后选择保留或移除，全部步骤与提醒处理后可进入白天。到期文字由说书人判断，不自动删除标记。

清单排序与并列显示的中英提醒来自 TPI；步骤筛选、完成状态及辅助提示属于本地工作流，条件结算仍由说书人决定。
